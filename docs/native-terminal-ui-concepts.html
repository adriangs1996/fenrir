Terminal Shell — two directions

Two opposed philosophies for the native shell, same workspace state in both: a Claude Code pane awaiting approval, an nvim pane, and a shell pane that just ran the test suite. Presence comes from hook-emitted OSC (D-038), prompts are dispatched into agent panes (D-040), there is no chat view (D-037). Toggle the palette and composer overlays to compare how each direction absorbs them.

The bet: chrome earns nothing. Opens like Ghostty — no sidebar, no pane headers, one statusline. Presence is a pulsing dot on the tab, an amber hairline on the focused pane, and one statusline word. Everything else lives behind ⌘P.

  1. Tabs are tmux windows (D-010), rendered as bare text in the titlebar. No favicons, no close buttons — kill panes with tmux bindings.
  2. Presence is one pulsing dot on the tab, sourced from hook OSC (D-038). Amber = needs you. No dot = working or idle; the statusline disambiguates.
  3. The statusline is the only persistent chrome. Attention text doubles as the jump affordance (⌘J focuses the exact pane).
  4. ⌘P is the whole nav model (D-029): workspaces by default, attention items surface at the bottom regardless of query.
  5. Focused-pane hairline is the resize-authority cue (D-011): the amber border marks the one viewport that sends authoritative resizes.
  6. Composer dispatches into the agent pane (D-040) — target is explicit, never ambiguous; the footer states the delivery guarantee.
B · operations deck

The bet: you run 4+ workspaces with agents in half of them — glanceability beats purity. Persistent Supacode-style sidebar with attention first, pane headers carry presence chips, status bar carries stream health. Chrome pays rent.

  1. Attention outranks navigation (D-027): awaiting-input agents pin to the top of the sidebar with a jump hotkey — the Supacode move, kept.
  2. Workspace rows are operational: presence badge (◉ agents needing you) and workflow badge (⚙ running) per row, row-level cached so high-frequency events don't repaint the sidebar (WS13).
  3. Remote profiles group and degrade visibly (D-032): a reconnecting remote workspace pulses red instead of silently disappearing.
  4. Tab dots mirror pane presence rolled up per tmux window, so attention survives tab switching.
  5. Pane headers carry agent identity: process, pane id, hooks version (D-039 integration status), and a presence chip — the anti-Ghostty bet.
  6. The status bar is stream health (WS20): ws latency, pane count, attention echo. Diagnostics one click away.

What to decide while looking at these

  • Chrome default: does the app open bare (A) with the sidebar as an on-demand surface, or open operational (B) and let minimalists collapse it? This decides WorkspaceShell's first-run state.
  • Presence encoding: is one amber accent + shape (A) enough for busy/awaiting/failed, or does chromatic coding (B: amber/green/red/violet) earn its extra vocabulary?
  • Pane headers: A says never (hover reveals identity), B says always (identity + hooks version + chip). Affects TerminalViewport host layout and vertical budget.
  • Where attention lives: statusline text with a jump key (A) vs a dedicated pinned sidebar section (B). Both must map to the palette ! domain either way (D-029).
  • Overlay language: hairline sheets that read as part of the terminal (A) vs elevated cards with radius/shadow (B). Whichever wins becomes the WorkspaceOverlays visual contract.
  • Status bar ownership: minimal session facts (A) vs stream/health telemetry (B) — decides how much of WS20 diagnostics gets ambient surface.
