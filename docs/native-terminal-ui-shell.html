Tree rows come from pane metadata and hook presence (D-038/D-039), never from scraping.   1. Quiet tmux tabs, kept from concept A (D-010): bare text in the titlebar, active underline in the theme accent, one pulsing dot rolling up pane presence per tmux window. No favicons, no close buttons.
  2. Attention outranks navigation (D-027): awaiting-input agents pin above the tree with a jump hotkey, mirrored in the palette ! domain.
  3. Agent rows come from hook presence (D-038/D-039): identity + state + pane target. Selecting one focuses the pane; it never writes to it.
  4. App rows are integration-detected panes (D-019 metadata + D-039 detection): nvim, gh-dash, hunks appear when Fenrir recognizes the pane process, with app-specific metadata (file, PR count, changed files). Unrecognized processes simply don't appear — no fake entries.
  5. Dev server rows are managed-process metadata over WS (D-034): passive status/port/latency rows, not a dedicated native surface. Row action = focus the linked pane or tail logs in one.
  6. Pane headers carry agent identity: process, pane id, hooks version (integration status), presence chip. The operations-deck bet, kept.
  7. The status bar is stream health (WS20): ws latency, pane count, attention echo, sidebar/palette hints.
  8. Titlebar productivity controls (D-045): a run split-button (idle: "run" primary script; running: stop, with a pulsing workflow-token indicator and ok-token label — both states toggleable in this mockup via the button or r; scripts execute as real tmux panes with managed-process metadata, which is what feeds the dev-servers group), an open-in-editor split-button showing the resolved default editor (dropdown picks/persists another target), and a notifications bell whose unread badge uses the attention token and opens the notifications panel.
  9. Pane attention ring (D-045): a pane whose agent awaits input draws a 1.5px ring in the attention slot on top of the normal border — driven by D-038 presence / D-043 notifications, never by scraping. Focus (accent border) and attention (ring) compose.
  10. Workspace row metadata (D-045): a muted latest-notification line (from the notifications model) plus listening-port chips (from localServers discovery contracts) under the workspace row; attention rows additionally tint their background. PR status/number joins only once a server-side PR-probe contract exists.

Contract notes for implementation

  • Themes are design tokens shared with Fenrir Desktop's registry (apps/web/src/lib/theme.ts ids: fenrir dark, pierre dark, catppuccin mocha, rose pine, kanagawa, tokyonight moon, nord…). One token set drives chrome, tree, presence, ANSI, and overlays — no surface may hardcode a color.
  • Sidebar default: visible, collapsible to zero chrome with ⌘B — collapsed state must keep attention reachable via titlebar bell + palette ! domain.
  • Tree data sources: agents from hook presence (D-038), apps from pane process/metadata detection (D-039 adapters decide which apps are "supported"), dev servers from managed-process WS contracts (D-034). No terminal scraping anywhere.
  • Tree rows are row-level cached (WS13): presence flaps update one row, never the tree. Collapsed workspaces roll their attention up into badges on the workspace row.
  • Presence coding is chromatic: attention amber, health green, failure red, workflows violet — each theme maps these four semantic slots to its own palette.
  • Titlebar controls are D-045 chrome that pays rent: run split-button (script definitions live in Settings, repository scope over global; scripts run as real tmux panes with managed-process metadata — never app-local child processes), open-in-editor split-button (target catalogue of editors/terminals/git clients/Finder/$EDITOR resolved against installed apps; per-repo default over global; pure client feature), notifications bell (unread badge in the attention token). Palette parity is mandatory: run/stop-script, open-in-editor, notifications-panel, and jump-to-unread all exist as palette actions and keybindings, so the controls stay optional chrome.
  • Notifications panel is an elevated card like the palette, fed by D-042 approval cards and D-043 generic OSC 9/99/777 notifications; unread rows are emphasized with the attention token and ⌘⇧U jumps to the latest unread. Notification title/body are user-visible content, excluded from diagnostics exports by default (D-031).
  • Attention treatment (D-045): awaiting-input panes get a themed ring in the attention slot; sidebar attention rows light up (background tint + dot) and sort into the attention section; the workspace row carries a muted latest-notification line and listening-port chips (existing localServers discovery contracts). PR status/number ships only when a server-side PR-probe contract exists — the client never shells out to gh or scrapes panes.
  • Resolved micro-question (D-045): dev-server start/stop is a titlebar/palette action through the run-script model — no dedicated row action needed; dev-server rows stay passive metadata (D-034).
  • Open micro-questions: does the tree auto-expand the active workspace only (mocked here)? Do app rows for tools without live metadata (hunks idle) show at all?
